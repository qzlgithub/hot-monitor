# 实时通知告警 Skill

用于设置和管理实时通知系统，在热点匹配时立即发送浏览器通知和邮件告警。

## 何时使用

使用此 Skill 当您需要：
- 配置热点匹配的自动通知
- 管理和查看所有接收到的告警
- 实现多渠道通知（浏览器推送、邮件、短信等）
- 设置通知的优先级和过滤规则
- 追踪用户对告警的响应（已读/未读）
- 建立 24/7 的监控告警系统

## 工作流

### 1. 自动告警生成流程
```
用户添加关键词
    ↓
系统后台监控 (每 15 分钟)
    ↓
发现匹配的热点
    ↓
AI 评估真实性和相关性
    ↓
通知评分 ≥ 5 分
    ↓
✅ 自动生成通知
    ├─ 浏览器通知
    ├─ 邮件告警
    └─ 通知中心记录
```

### 2. 获取所有通知
```bash
GET /notifications
# 返回最新的通知列表（按时间倒序）
# 包含：
#   - 通知标题和内容
#   - 关键词和来源
#   - 已读/未读状态
#   - 创建时间戳
```

### 3. 标记为已读
```bash
PATCH /notifications/{id}/read
# 将通知标记为已读（消除未读标记）
```

### 4. 删除通知
```bash
DELETE /notifications/{id}
# 删除不需要的通知
```

## 通知数据结构

```json
{
  "id": "唯一标识",
  "title": "通知标题",
  "message": "通知内容描述",
  "type": "success|warning|info",
  "keyword": "触发该通知的关键词",
  "source": "热点来源 (Twitter/Web/Zhihu/Xiaohongshu)",
  "timestamp": "2026-08-15T14:30:00Z",
  "read": false
}
```

## 通知类型说明

| 类型 | 分数范围 | 用途 | 示例 |
|-----|--------|-----|-----|
| **success** | 8-10 | 高热度热点 | AI 突破、融资等重大新闻 |
| **warning** | 6-8 | 中等热度热点 | 行业新闻、产品更新等 |
| **info** | 5-6 | 低热度热点 | 相关提及、讨论等 |

## 通知规则引擎

系统自动应用以下规则：

```
规则 1: 去重
       相同标题的热点不重复通知
       
规则 2: 时间衰减
       同一热点不在 24 小时内重复通知
       
规则 3: 优先级
       高热度优先显示，紧急 ⚠️ 标记
       
规则 4: 过滤
       虚假热点自动过滤（AI 识别）
       
规则 5: 聚合
       相关话题自动聚合为一条通知
```

## 通知管理

### 查看通知统计
```bash
# 获取所有通知
GET /notifications
# 返回的数组包含以下统计信息：
# - 总未读数
# - 按关键词分组
# - 按来源分组
# - 按类型分组
```

### 批量操作
```bash
# 全部标记为已读（前端功能）
notifications.forEach(n => markAsRead(n.id))

# 清理旧通知（7天以上）
DELETE /notifications?older_than=7days
```

### 通知优先级排序
```
优先级从高到低:
1️⃣  warning (中等到高热度)
2️⃣  success (高热度确认)
3️⃣  info (低热度提及)
```

## 邮件通知配置

### Gmail 配置示例
```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASS=your-16-char-app-password
SMTP_FROM=noreply@hotmonitor.local
```

### 获取 Gmail 应用专用密码
1. 启用 2 步验证
2. 访问 myaccount.google.com/apppasswords
3. 生成 16 位密码
4. 粘贴到 SMTP_PASS

## 最佳实践

### ✅ 建议做法

1. **及时查阅通知**
   - 定期打开通知中心
   - 标记已读以跟踪进度

2. **优化关键词**
   - 定期调整监控词汇
   - 根据通知相关性调整
   - 移除无关关键词

3. **设置通知频率**
   - 不要添加过多关键词
   - 建议 3-10 个关键词
   - 根据业务需要调整

### ❌ 需要避免

1. 添加过于宽泛的关键词
   - ❌ "热点"、"新闻"
   - ✅ "AI编程"、"ChatGPT"

2. 忽视通知内容
   - ❌ 让通知堆积
   - ✅ 定期清理、标记已读

3. 配置错误
   - ❌ SMTP 密码错误
   - ✅ 定期测试邮件功能

## 常见问题

### Q: 为什么没有收到通知？
A: 检查以下项：
   1. 是否添加了关键词？
   2. 浏览器是否允许通知权限？
   3. 是否有相关热点发现？（等待 15 分钟）

### Q: 通知频率太高/太低？
A: 调整方法：
   - 频率太高：减少关键词数量，使用更具体的词汇
   - 频率太低：添加更多相关关键词

### Q: 如何配置邮件通知？
A: 需要在后端配置 SMTP（见上面的邮件配置章节）
